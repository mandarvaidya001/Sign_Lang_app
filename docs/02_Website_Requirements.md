# Website Requirements

# Purpose

The purpose of this website is to provide a simple, clean, and interactive demonstration of the Sign Language Recognition System.

This is **not** a marketing website or a portfolio landing page.

The primary goal is to allow users to experience the AI model through a minimal and intuitive interface.

The website should prioritize functionality, usability, and clarity over unnecessary visual complexity.

---

# Website Type

Minimal AI Demonstration Web Application

---

# Primary Goal

Allow users to:

- Launch the application
- Select a recognition mode
- Use the webcam for real-time prediction
- View recognized text
- Build words or sentences using available controls
- Hear the final text through text-to-speech

The entire experience should require as few steps as possible.

---

# User Flow

Landing Page

↓

Recognition Mode Selection

↓

Live Recognition Screen

↓

Text Formation

↓

Speech Output

---

# Screen 1 — Landing Page

## Purpose

Introduce the application with a clean and minimal interface.

## Components

- Project title
- Short one-line description
- Start button

## Title

Sign Language Recognition

## Subtitle

Real-time AI Powered Sign Language Recognition using Computer Vision and Deep Learning.

## Primary Button

Start

## Expected Behaviour

When the user clicks the Start button, navigate to the Recognition Mode Selection screen.

---

# Screen 2 — Recognition Mode Selection

## Purpose

Allow users to choose the recognition mode.

## Available Modes

### Letter Recognition

Status:

Implemented

Action:

Navigate to Live Recognition Screen.

---

### Word Recognition

Status:

Implemented

Action:

Navigate to Live Recognition Screen.

---

### Sentence Recognition

Status:

Coming Soon

Action:

Disabled.

Should not allow interaction.

Display a small "Coming Soon" label.

---

# Screen 3 — Live Recognition

## Purpose

Provide the main AI demonstration.

This is the most important page of the application.

---

## Layout

The webcam preview should be positioned at the center of the page.

Below the webcam preview should be the prediction section.

Below the prediction section should be the text formation section.

Below the text formation section should be the control buttons.

Everything should remain centered.

---

# Webcam Section

Requirements:

- Large camera preview
- Rounded corners
- Clean border
- Responsive layout
- No unnecessary overlays

The camera should be the visual focus of the page.

---

# Prediction Section

Display:

Current Prediction

Example:

APPLE

The prediction should update in real time.

The prediction should appear below the webcam instead of inside the webcam preview.

---

# Text Formation Section

Display the complete text generated by the user.

Example:

HELLO HOW ARE YOU

The text should continuously update as the user interacts with the controls.

---

# Control Buttons

Place the buttons below the text formation area.

Required buttons:

- Space
- Enter
- Clear
- Quit

Each button should have a consistent appearance.

---

# Button Behaviour

## Space

Insert a space into the generated text.

---

## Enter

Finalize the current text.

Trigger text-to-speech.

Play the generated speech through the computer speakers.

---

## Clear

Remove all generated text.

Reset the prediction display if appropriate.

---

## Quit

Stop webcam capture.

Stop prediction.

Return to the Landing Page.

Release camera resources properly.

---

# Text-to-Speech

After the user presses Enter:

- Convert the generated text into speech.
- Play the speech automatically.
- Do not require additional user interaction.

---

# Responsive Design

The website should work correctly on:

- Desktop
- Laptop
- Tablet

Mobile support can be considered later.

---

# Accessibility

The interface should:

- Use high contrast
- Have readable typography
- Use large buttons
- Keep controls easy to understand
- Minimize distractions

---

# Performance

The application should:

- Load quickly
- Open the camera efficiently
- Keep prediction responsive
- Avoid unnecessary animations that reduce performance

---

# Scope

The current version should only implement:

- Landing Page
- Recognition Mode Selection
- Live Recognition Screen

No login system.

No dashboard.

No user profiles.

No database.

No analytics.

No unnecessary pages.

The focus is demonstrating the AI model.

---

# Success Criteria

A first-time user should be able to:

1. Open the website.
2. Click Start.
3. Select Letter or Word Recognition.
4. Allow camera access.
5. Perform sign language gestures.
6. Watch predictions appear in real time.
7. Build text using the controls.
8. Press Enter.
9. Hear the generated speech.

The complete process should feel simple, intuitive, and require minimal explanation.
